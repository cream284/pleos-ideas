User Story / Priority 3

세 후보, 사용자가 느낄 변화

기술이 해결하는 일과, 그 결과 사용자가 되찾는 마음을 함께 비교합니다.

아래 이야기는 기획을 위한 가상 사용자 시나리오입니다. 실제 인터뷰나 검증된 효과를 뜻하지 않습니다.

우선 검토 후보·전달 문장공감할 수 있는 이야기감성 포인트·감정 변화감성을 경험으로 만드는 기능
방문 업무 차량 비서
“오늘의 수고가 빠짐없이 남도록.”		마지막 고객의 집을 나와 차에 앉는다. 저녁 약속 전, 오늘 처리한 일과 다시 방문할 곳을 떠올리며 보고서를 써야 한다. 정차한 차 안에서 짧게 남긴 메모가 방문 기록에 연결되고, 하루 보고 초안이 정리된다.수고를 알아주는 동료 같은 차
빠뜨릴까 하는 부담 → 정리됐다는 안도감
핵심 정서: 인정·성취감·일상으로의 복귀		STT 메모 → 방문 건에 연결 → 사용자가 완료·보류 확인 → 보고 초안 생성.
TTS는 다음 일정 안내. 자동 업무 완료 판정과 보고 시간 절감은 검증 전 약속하지 않음.
렌터카 반납 도우미
“여행의 마지막까지, 마음 편하게.”		가족 여행을 마치고 공항으로 돌아가는 길. 반납 시간과 충전 조건, 낯선 반납 입구가 신경 쓰인다. 앱이 계약과 현재 상태를 비교해 남은 준비를 보여주고, 선택한 충전 경유지와 반납 입구를 안내한다.낯선 절차를 함께 정리해주는 안내자
불확실함·실수 걱정 → 준비 상황을 아는 안도감
핵심 정서: 통제감·배려·여행의 좋은 마무리		계약 목표와 SOC 비교 → 준비 체크리스트 → 충전·반납 안내.
계약상 조건을 설명하고 진행 상황을 확인. 추가 요금 면제·비행기 정시 도착은 보장하지 않음.
여러 차량의 동행 여행
“차는 달라도, 여행은 함께.”		부모님 차와 우리 차가 함께 출발했다. 한 차는 충전이 필요하고 다른 차에서는 아이가 쉬고 싶어 한다. 각 차의 필요가 공통 정차 후보에 반영되고, 합의한 다음 만남의 장소가 두 차량의 내비에 적용된다.각자의 속도와 사정을 배려하는 동행
말 꺼내기 미안함·조율 부담 → 함께 배려받는 느낌
핵심 정서: 연결감·소속감·서로를 돌보는 마음		차량 상태·휴식 요청 공유 → 후보 제안 → 합의 → 각 차량 안내.
상태 공유는 동의 기반. 서버 통신과 연결 단절 시 처리 필요. 차량 간 간격 유지·안전 추종 기능은 제외.
발표의 순서: 한 사람의 구체적인 순간 → 불편할 때의 감정 → 앱에서 달라지는 행동 → 되찾는 마음. 감성 포인트는 사용자 공감을 위한 기획 가설이며 공식 가산점이나 검증된 효능이 아닙니다.

평가 기준으로 다시 보기

아래 평가는 팀의 정성적 판단입니다. 공식 배점·총점·수상 확률을 뜻하지 않습니다.

후보차량특화성창의성기술 활용성사업성·결정 과제
여러 차, 한 여행차량마다 다른 에너지 상태가 공동 목적지를 바꿈
단순 위치 공유 앱과 비교해 조율 시간 감소를 보여줘야 함		차량별 조건을 함께 고려하는 그룹 의사결정
유사 서비스 조사 전 독창성을 단정하지 않음		상태 변화 → 후보 변경 → 각 차량 내비 적용
API 개수보다 이 흐름의 실제 동작이 중요		동행 여행이라는 구체적 사용 맥락
동시 설치 장벽과 낮은 여행 빈도 해소 필요
내게 편한 길실제 차량 이동 경험이 다음 이동 결정에 반영

기존 초보·골목 회피 기능과 차이 조사 필요		경로 맥락과 내비 안내 연결
핵심 경로 제약은 공개 SDK만으로 충족되지 않을 수 있음		초보·복귀 운전자와 교육기관
필요 기간 종료 후 이탈을 반영한 상품 설계 필요
반납 전, 한 번에계약과 실제 차량 상태가 직접 연결
기본 잔량 화면에 없는 반납 준비 의사결정 필요		반납이라는 명확한 순간을 하나의 흐름으로 구성
기존 렌터카 앱의 반납 기능과 중복 조사		차량 상태 비교와 경유지·목적지 안내 결합
실제 값 변경에 따라 준비 항목이 바뀌는 시연		지불 주체와 업무 비용이 구체적

확인된 기준과 남은 가설

공식 심사 기준

1차는 차량특화성·창의성·기술 활용성·사업성을 평가합니다. 세부 배점은 비공개이며 2차 PT 기준은 추후 안내입니다.

시연 영상과 소스·APK 등 개발 산출물에 단계별 가산점이 있습니다. 이 HTML 자료 자체는 동작하는 차량 앱의 개발 산출물을 대체하지 않습니다.

API 사용 원칙

공모전이 명시한 Vehicle·NaviHelper·FusedLocation·STT·TTS를 검토 범위로 삼습니다. 실제 실행 권한·차종 지원·에뮬레이터 동작은 별도로 확인하며 Gleo Interface는 이번 구현 범위에서 제외합니다.

문서에 API가 존재해도 차종·권한·capability·실행 환경에서 검증해야 합니다. UWB는 공개 API를 확인하지 못해 핵심 전제에서 제외했습니다.

확인 기준: 2026년 10월 26일. 고객 수요·과금 모델·차별성 평가는 검증 전 가설입니다.

  4. Vehicle SDK 공식 문서 — 차량 상태 도메인과 capability 확인.
