문제와 첫 고객

설치·점검·수리 담당자는 방문지 안내, 고객 주소 재입력, 작업 메모와 일일 보고를 여러 앱에서 처리합니다. 이동과 업무 기록이 분리되어 있습니다.

먼저 만날 사용자

하루 여러 현장을 방문하는 소규모 서비스 업체. Pleos 차량을 실제 업무에 사용하는 팀부터 검토.

현재의 해결 방법

배차 앱의 주소를 내비게이션으로 옮기고 작업 후 휴대폰 메모를 다시 보고서에 입력합니다.

문제의 강도와 빈도는 아직 검증하지 않았습니다. 인터뷰에서는 최근 실제 사례와 현재의 대처 방법부터 확인합니다.

04 / 02 — 06

차량 화면에서 이어지는 경험

차량 화면에서 다음 방문을 안내받고 정차 후 완료를 직접 확인하면 기록과 다음 방문 안내가 연결됩니다.

01

업무 목록
샘플 또는 제휴 업무 서버에서 오늘의 방문 순서를 가져옵니다.

02

다음 방문 안내
사용자가 고른 방문지를 NaviHelper로 전달합니다. 자동 최적화는 별도 개발 범위입니다.

03

정차 후 기록
사용자가 작업 완료·보류를 선택하고 짧은 메모를 입력합니다. 음성은 접근 확인 후 추가합니다.

04

하루 보고
명시적으로 확인한 작업과 지원되는 이동 기록으로 보고서 초안을 만듭니다.

Vehicle State / Odometer방문 업무에 연결된 이동 거리 기록 보조문서 확인 · 업무/개인 이동 구분 필요

04 / 04 — 06

누가, 왜 계속 사용하는가

사업 가설

업체 단위 사용자당·차량당 구독을 가설로 둡니다. 기존 배차·현장관리 도구에 추가 비용을 낼 만큼 중복 입력과 보고 시간이 줄어야 합니다.

고객 검증에서 볼 것

주소 전환·보고 작성에 실제 쓰는 시간, 하루 방문 빈도, 미기록 건수, 업체의 도입 의향과 차량 보유 현황을 확인합니다.

가격·시장 규모·MAU·유지율은 조사 전 임의 수치를 넣지 않았습니다. 구독 모델 자체가 공식 가산점이라는 근거도 없습니다.

가장 큰 불확실성

문 열림이나 도착만으로 작업 완료를 판정하지 않습니다. 주행 중 텍스트 입력을 허용하지 않으며 UI 제한은 실제 CarUxRestrictions를 따라 구현해야 합니다.
