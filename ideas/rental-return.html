문제와 첫 고객

반납 시간이 다가오면 고객은 주유·충전 기준, 반납 장소의 실제 진입구, 남은 시간과 추가 비용을 각각 확인해야 합니다.

먼저 만날 사용자

Pleos 탑재 차량을 운영하는 렌터카 사업자와 이용 고객. 계약 연동이 가능한 사업자를 첫 고객으로 가정.

현재의 해결 방법

계약 문자·종이와 차량 계기판을 번갈아 보고, 주유소·충전소와 반납 위치를 따로 검색합니다.

문제의 강도와 빈도는 아직 검증하지 않았습니다. 인터뷰에서는 최근 실제 사례와 현재의 대처 방법부터 확인합니다.

차량 화면에서 이어지는 경험

반납 조건과 현재 상태의 차이를 확인하고, 사용자가 고른 주유·충전 경유지와 반납 입구를 순서대로 안내합니다.

01

계약 불러오기
제휴 서버 또는 수동 입력으로 반납 시간·장소·요구 연료/SOC를 저장합니다.

02

상태 비교
지원되는 차량 값으로 목표와 현재 상태의 차이를 보여줍니다.

03

준비 동선
검증된 주유소·충전소를 경유해 반납 입구로 가는 안내를 요청합니다.

04

반납 확인
계약 기준 체크리스트와 확인 시각을 보여줍니다. 최종 정산·완료 판정은 운영사가 합니다.

03 / 04 — 06

누가, 왜 계속 사용하는가

사업 가설

사업자 대상 차량당 또는 반납 건당 과금을 검토합니다. 고객의 연료 부족 문의, 반납 지연, 직원 확인 업무가 실제 줄어드는지 입증해야 합니다.

고객 검증에서 볼 것

반납 관련 문의 유형과 빈도, 고객 준비 시간, 직원 확인 시간, 추가 비용 분쟁 사례를 운영사에서 확인합니다.

가격·시장 규모·MAU·유지율은 조사 전 임의 수치를 넣지 않았습니다. 구독 모델 자체가 공식 가산점이라는 근거도 없습니다.

3인 팀이 먼저 증명할 것

최소 구현 범위

EV 또는 내연기관 한 유형만 선택하고, 수동 계약 입력·차량 상태 차이·경유지 1곳·반납 체크리스트를 구현합니다.

시연 장면

동일 계약에 대해 목표 미달 상태와 충족 상태를 바꿔, 준비 항목과 주유·충전 경유지 필요 여부가 달라지는 과정을 보여줍니다.

가장 큰 불확실성

외관 손상, 자동 정산, 결제, 운영사 반납 완료는 별도 기능입니다. 예상 에너지와 비용은 보장값이 아닌 추정으로 표시합니다.

역할 분담 초안

담당 1: 차량 상태·단위 처리 · 담당 2: 계약 규칙·운영사 조사 · 담당 3: 반납 흐름 UI·내비 연동

공식 자료와 확인 기준 보기
  1. 공모전 공식 심사·시상 안내 — 1차 평가 항목, 비공개 배점, PT 기준 추후 안내.
  2. SDK 사용 신청 안내 — Vehicle State·NaviHelper 사용 가능, 일부 SDK 준비 중 표시.
  3. NaviHelper 공식 문서 — 목적지·경유지 요청과 정보 조회.
  4. Vehicle SDK 공식 문서 — 차량 상태 도메인과 capability 확인.
